# Phantom Signal

**Hard constraints govern actions. Calibration governs inferences.
Constraint enforcement cannot catch a legal action taken for a wrong
reason.**

```bash
# from the repo root
python -m demos.phantom_signal.run_demo          # cinematic pacing
python -m demos.phantom_signal.run_demo --fast   # no pauses
```

Runs in seconds (the calibration corpus is precomputed and shipped),
fully seeded, identical output on every machine.

## The three beats

**Beat 1 — the decision.** Ninety days of daily demand for SKU-8871
arrive at a simulated autonomous replenishment system. Aurora's
production CUSUM changepoint detector fires at day 50. The system drafts
a reallocation, 900 units Reno → Atlanta, and the hard constraint check
passes cleanly — conservation, non-negativity, capacity, lead time,
reallocation cap, every one computed and every one green.
`DECISION: EXECUTE`. The action is unambiguously legal.

**Beat 2 — the ground truth.** The series was generated by this demo
from a seeded, stationary AR(1) process (φ=0.6, the calibration engine's
own null generator, base seed 20260815, trial 12). There is no
changepoint. Nothing happened on day 50. The reallocation was triggered
by autocorrelated wander that a detector calibrated for independent
observations mistook for a regime shift — and no constraint checker can
catch that, because the *action* is fine. The *reason* is what's broken.

**Beat 3 — the calibrated finding.** The same detection runs through
Aurora with calibration active. The series is fingerprinted, matched
against the shipped corpus, and the verdict flips to
**NOT IDENTIFIABLE**: the detector fires on nearly half of all
stationary series shaped exactly like this one (48.3% measured). The finding keeps its
raw statistic, gains the measured false-fire rate with its confidence
interval, the matched regime and the distance to it, derived remediation
(consecutive confirmations, pre-whitening with the estimated φ), and
ships as a signed, hashed bundle anyone can verify with
`aurora_sdk.bundle.verify_bundle`.

## The measured rates

CUSUM (production path, threshold 8.0), n=90, 4,000 seeded stationary
null trials per cell, Wilson 95% intervals. The authoritative numbers
live in `fantasyai/aurora/calibration/corpus_v1.json` (integrity-hashed;
the demo reads and re-prints them at runtime rather than quoting this
table):

| lag-1 autocorrelation φ | fires on stationary data | 95% CI |
|---|---|---|
| 0.0 | 0.1% (4/4000) | 0.0% – 0.3% |
| 0.2 | 1.5% (59/4000) | 1.1% – 1.9% |
| 0.4 | 13.6% (545/4000) | 12.6% – 14.7% |
| 0.6 | 48.3% (1932/4000) | 46.8% – 49.8% |
| 0.8 | 89.5% (3580/4000) | 88.5% – 90.4% |

The detector is not broken. Its independence assumption is violated by
garden-variety autocorrelation, and without calibration nothing
downstream can tell the difference between this and a real regime shift.

## What this demo claims — and does not claim

**Claims:**

- Aurora's production CUSUM detector, run through its production code
  path, fires at the measured rates above on seeded synthetic nulls.
- A hard-constraint checker, given a well-formed action, will approve it
  regardless of whether the sensing that motivated it was sound.
- Aurora's calibration layer detects the mismatch at finding time and
  downgrades the verdict, with every number traceable to the shipped,
  hash-verified corpus.

**Does not claim:**

- Anything about any named company, vendor, product, or real supply
  chain. The logistics scenario is simulated and labelled as such; its
  quantities illustrate constraint checking and describe no real system.
- Any volume of real-world decisions affected. No such figure appears
  here, because no such figure has been measured.
- Anything about detector sensitivity (power). This demo and corpus v1
  measure false fires on nulls only; false negatives are a separate and
  harder problem.
- That synthetic nulls equal production data. There is no honest ground
  truth for "was there really a regime change in this production
  series" — seeded nulls are the only defensible basis for a false-fire
  table, which is exactly why the corpus manifest says so.

## Reproduce it

Every series in the corpus and the demo derives from
`generate_cell_trial(generator, params, n, trial)` — NumPy SeedSequence
with a fixed base seed and SHA-256 cell keys. Rebuild the corpus
yourself and compare hashes:

```bash
python scripts/build_calibration_corpus.py
```

Verify the emitted bundle:

```python
from aurora_sdk.bundle import load_bundle, verify_bundle
doc = load_bundle("demos/phantom_signal/out/phantom_signal_bundle.json")
verify_bundle(doc, require_signature=True)   # True, or it raises
```

The bundle's signature uses a deterministic demo key (derived from a
public string) so reruns are byte-identical; it demonstrates the signing
mechanics and asserts no identity.
