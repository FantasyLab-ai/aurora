# Aurora pre-launch sprint — BEFORE capture (legacy behaviour)

Static snapshot of the pre-sprint behaviour against the same synthetic
NOAA buoy dataset. The "before" cannot be regenerated by running the
current code (the bugs were fixed); these notes document what the
system used to produce so the after/before delta is auditable.

## Same input

- Synthesised NOAA buoy dataset, 8,760 rows × 6 cols, 3 engineered storm
  windows producing 47 real anomalies above the runner's significance
  threshold.

## What the legacy system produced

### `/api/run` response shape

Synchronous — blocked the request for 90+ seconds while the runner
ran. Frontend tab spun on a 10-minute fetch with no progress.

```json
{
  "ok": true,
  "run_dir": ".../20260505_142318__noaa_buoy_2024",
  "returncode": 0,
  "elapsed_seconds": 94.2
}
```

No `run_id`, no `async` field, no `status_url`.

### `/api/state` response — Bug 1 (numpy serialization)

When called on a real run, `/api/state` would return HTTP 500 on any
connector that produced int64 columns (USGS magnitudes, OpenML class
counts, World Bank year columns). Browser network tab:

```
HTTP/1.1 500 INTERNAL SERVER ERROR
TypeError: Object of type int64 is not JSON serializable
```

Frontend would fall back to mock data with this banner:

```
⚠ no live analysis — showing mock data (API error: Unexpected token '<'...)
```

### `/api/state` response — Bug 2 (top-N truncation)

When the runner emitted 47 anomalies, the response carried only **10**:

```json
{
  "anomalies": [ /* 10 entries — truncated */ ],
  "findings": [
    {
      "title": "Anomaly in humidity_pct at row 4231",
      "severity": "info",
      "description": "humidity=high z=+1.8"
    }
    /* note: no critical anomalies in findings even though 7 existed
       in the data, because the runner-emitted top-10 happened to be
       ranked by score not severity */
  ]
}
```

Copilot fallback narrative:
> I found 10 anomalies (0 critical).

### Bug 3 (run staleness)

Frontend never re-rendered after Tier 2 / Tier 3 completed. User had
to manually refresh the browser to see updated findings. Tier
transitions in the sampling badge appeared only on refresh.

### Bug 4 (run identity invisibility)

Top-right header read `RUN 20260501-1442` (a static placeholder).
The dataset rail showed one filename, the cube showed another's data,
and there was no source-of-truth answer to "which run am I looking at?"

See `../after/api_state.json`. The headline deltas:

| Metric | Before | After |
|--------|--------|-------|
| Anomalies surfaced | 10 (capped) | **47** (full) |
| n_total_at_this_severity recorded | no | yes |
| Critical findings synthesised | 0 (filter-after-truncate bug) | 5 (filter-then-sort) |
| run_meta block on /api/state | absent | **17 fields populated** |
| /api/run async kickoff | no (90s+ block) | yes (<200ms) |
| /api/run/status endpoint | absent | present |
| numpy types in JSON response | leaked → 500 | sanitised |
| Frontend mock-data fallback | silent on errors | explicit error UI |
| Sampling badge auto-updates | refresh required | yes (polling) |
| Tier 3 button after T2 | refresh required | yes |
| Referent labels (Phase A) | "row 1248" | timestamp / event / position |
| Decision contract framing | absent | 21 default contracts |
| Seed-aware ranking | absent | 2 sections + Spearman ≥ 0.70 |
| Domain templates | 7 | **10** (+economics, sports, logistics) |
| Network-shape detection | absent | yes |
| Overnight learning | wired but disabled | scheduler + draft changelog |
| Public /learning page | absent | yes (token-gated review gate) |
| Test count | 274 | **566** (+292) |
